# Regional observability queries

Observability RPCs use the same selected regional control-plane address and bearer credential as the rest of the API. Each regional control plane queries its own ClickHouse through a separate observability proxy process. Worker-cluster membership and liveness do not select a query backend; clients send each request once. Regional ClickHouse databases do not replicate across regions, and clients do not fan out across control-plane addresses.

The API mounts `/loco.observability.v1.ObservabilityProxyService/` as a streaming HTTP forwarding route to the private `OBSERVABILITY_PROXY_URL` origin. The proxy authorizes workspace READ permission through `CONTROL_PLANE_URL` and executes queries. With a gateway, that RPC prefix can route directly to the proxy on the API hostname. The `loco-control-plane` chart contains that route but remains WIP and is not installed by platform releases. Local Tilt and the observability e2e suites use the API forwarding route.

The public query origin, private proxy origin, private ClickHouse reader/migrator DSNs and OTLP ingestion address serve separate purposes. Configure the API with, for example, `OBSERVABILITY_PROXY_URL=http://127.0.0.1:8050`; configure clients with the API address. Never advertise the private proxy or ClickHouse addresses to clients. An absent/unreachable proxy returns `Unavailable` through the API.

`QueryLogs.regions` and `excludedRegions`, and the matching `TailLogs` fields, filter the recorded `loco.region` resource attribute. Inclusions use OR; exclusions remove any matching region after inclusion. An empty inclusion list permits all regions. Matching is case insensitive; one trailing `*` matches a prefix (`us-*`). Each list allows up to 100 patterns of 128 characters. These typed filters do not relax the reserved `loco.` label namespace guardrail. The dashboard's `@region` and `-@region` tokens map to these filters; they do not select an endpoint. Each log row displays its own recorded region.

Log and metric queries with an empty `resourceIds` list read all resources inside the authorized workspace, including historical resources that no longer appear in the current resource list. Environment and region metric filters still narrow that workspace. Resource-page metric queries include the deployment's environment and region in both request and cache identity. Dashboard telemetry queries use the ordinary authenticated API transport, whose identity also separates query caches between control-plane addresses.

Log response cursors are opaque. Send them unchanged with the original filters; do not decode them as dates or merge independently paginated worker results. Changing filters resets paging. No current clusters or resources are required before querying history; the query RPC's permission/error/empty result determines the displayed state.

The former `GetObservabilityAccess` discovery service and cluster proxy-endpoint database column are removed. Clients using that RPC must migrate to the configured API address. The schema follows the repository's in-place migration policy; existing databases must be recreated or have the obsolete column removed separately.
